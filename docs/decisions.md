# Frontend decisions

- **B1 — Tooling, SPA mode, query client.** Test stack is vitest 4 + jsdom + Testing Library (`npm run test`), with `@vitejs/plugin-react` 5.2 (already installed, works with vite 8.1.5). TanStack Start 1.168.32 does not accept `defaultSsr` in `createRouter` (TS2353), so SSR is disabled with `ssr: false` on the root route (`createRootRouteWithContext` options) instead. The router's `QueryClient` uses `staleTime: 30_000`, `retry: 1` (replaced by the `ApiError`-aware retry in B3) and `refetchOnWindowFocus: false`. `SSRProvider` (Fluent) removed from the root; other Fluent usage stays until B20. `.env` is git-ignored; `.env.example` documents `VITE_API_BASE_URL`.
  - **Baselines (pre-existing skeleton, not fixed here):** `npm run lint` reports about 5.3k problems, almost all `prettier/prettier` "Delete ␍" CRLF line-ending errors on the imported files (5311 at the initial commit); `npx tsc --noEmit` reports 35 errors, all in `lcms-app.tsx`, `login-page.tsx`, `lcms-api.ts` (strictness flags such as `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`). B1 adds no new tsc errors. The edited lines in `router.tsx` and `__root.tsx` follow those files' CRLF endings, so they add a few of the same CRLF lint errors; new files (`vitest.config.ts`, `src/test/*`, `utils.test.ts`) lint clean.
- **B1b — Line endings normalised to LF.** Added `.gitattributes` (`* text=auto eol=lf`, binaries marked, lock files left untouched) and converted tracked text files to LF with no content changes. New baseline: `npm run lint` 143 problems (136 prettier formatting errors in skeleton files, 7 warnings), down from ~5.3k; `npx tsc --noEmit` still exactly 35 pre-existing errors (32 `lcms-app.tsx`, 2 `login-page.tsx`, 1 `lcms-api.ts`).
- **B2 — Typed API contract.** `npm run api:types` (openapi-typescript 7.13) generates `src/lib/api/schema.d.ts` from `http://localhost:4000/docs/json` (all paths generated, no errors); it is committed, never hand-edited, and excluded from eslint/prettier. `src/lib/api/types.ts` holds the helpers (`ApiResponse`, `ApiBody`, `ApiQuery`) and every named DTO alias; `types.check.ts` is a compile-time guard (tsc fails on drift).
  - **Overrides (only one):** the OpenAPI types `role` as plain `string` in `/auth/me` and `/auth/login`, so `Profile` and `LoginResponse.user` narrow it to `UserRole` via the internal `WithRole` helper. Everything else resolved correctly: CaseDto status/priority/slaState unions, `*Name` fields `string | null`, `estimatedValue` `number | null`, all `CaseListQuery` fields (`open` is the literal `"true"`), DashboardDto tiles (incl. `assignedToMe`, `unassigned`), `myAssignedCases?`, `managerPanels?`.
  - **Login vs Profile:** the `/auth/login` response `user` has exactly the same fields as `/auth/me` (id, fullName, email, designation, role, department/entity/businessUnit id+name), so it IS a full Profile (`Equal<LoginResponse['user'], Profile>` is guarded). Login also returns `accessToken`/`refreshToken`, which the app ignores.
  - **Aliases exported:** `UserRole, Profile, LoginResponse, CaseDto, CaseListDto, CaseListQuery, CreateCaseBody, DashboardDto, CaseStatus, CasePriority, SlaState, UserListDto, UserDto, NotificationListDto, CaseAuditDto, CommentListDto, DocumentListDto, InfoRequestListDto, AuditListDto, SlaComplianceReportDto, AgeingReportDto, VolumeByCategoryReportDto, VolumeByOrganisationReportDto, RepWorkloadReportDto, CaseCategoryListDto, CaseTypeListDto, DepartmentListDto, EntityListDto, BusinessUnitListDto, ClosureOutcomeListDto, RoutingRuleListDto`. Baselines unchanged: lint 143, tsc 35.
  - **Port note:** the backend `.env.example` default `PORT` is 3000, while this repo's `api:types` and `.env.example` use 4000 (the dev backend `.env` sets `PORT=4000`). `types.check.ts` guards fail on `never`, `any` and `unknown` DTOs and use exact `Equal` checks on status/priority/slaState/estimatedValue/requesterName/role.
