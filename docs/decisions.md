# Frontend decisions

- **B1 — Tooling, SPA mode, query client.** Test stack is vitest 4 + jsdom + Testing Library (`npm run test`), with `@vitejs/plugin-react` 5.2 (already installed, works with vite 8.1.5). TanStack Start 1.168.32 does not accept `defaultSsr` in `createRouter` (TS2353), so SSR is disabled with `ssr: false` on the root route (`createRootRouteWithContext` options) instead. The router's `QueryClient` uses `staleTime: 30_000`, `retry: 1` (replaced by the `ApiError`-aware retry in B3) and `refetchOnWindowFocus: false`. `SSRProvider` (Fluent) removed from the root; other Fluent usage stays until B20. `.env` is git-ignored; `.env.example` documents `VITE_API_BASE_URL`.
  - **Baselines (pre-existing skeleton, not fixed here):** `npm run lint` reports about 5.3k problems, almost all `prettier/prettier` "Delete ␍" CRLF line-ending errors on the imported files (5311 at the initial commit); `npx tsc --noEmit` reports 35 errors, all in `lcms-app.tsx`, `login-page.tsx`, `lcms-api.ts` (strictness flags such as `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`). B1 adds no new tsc errors. The edited lines in `router.tsx` and `__root.tsx` follow those files' CRLF endings, so they add a few of the same CRLF lint errors; new files (`vitest.config.ts`, `src/test/*`, `utils.test.ts`) lint clean.
- **B1b — Line endings normalised to LF.** Added `.gitattributes` (`* text=auto eol=lf`, binaries marked, lock files left untouched) and converted tracked text files to LF with no content changes. New baseline: `npm run lint` 143 problems (136 prettier formatting errors in skeleton files, 7 warnings), down from ~5.3k; `npx tsc --noEmit` still exactly 35 pre-existing errors (32 `lcms-app.tsx`, 2 `login-page.tsx`, 1 `lcms-api.ts`).
- **B2 — Typed API contract.** `npm run api:types` (openapi-typescript 7.13) generates `src/lib/api/schema.d.ts` from `http://localhost:4000/docs/json` (all paths generated, no errors); it is committed, never hand-edited, and excluded from eslint/prettier. `src/lib/api/types.ts` holds the helpers (`ApiResponse`, `ApiBody`, `ApiQuery`) and every named DTO alias; `types.check.ts` is a compile-time guard (tsc fails on drift).
  - **Overrides (only one):** the OpenAPI types `role` as plain `string` in `/auth/me` and `/auth/login`, so `Profile` and `LoginResponse.user` narrow it to `UserRole` via the internal `WithRole` helper. Everything else resolved correctly: CaseDto status/priority/slaState unions, `*Name` fields `string | null`, `estimatedValue` `number | null`, all `CaseListQuery` fields (`open` is the literal `"true"`), DashboardDto tiles (incl. `assignedToMe`, `unassigned`), `myAssignedCases?`, `managerPanels?`.
  - **Login vs Profile:** the `/auth/login` response `user` has exactly the same fields as `/auth/me` (id, fullName, email, designation, role, department/entity/businessUnit id+name), so it IS a full Profile (`Equal<LoginResponse['user'], Profile>` is guarded). Login also returns `accessToken`/`refreshToken`, which the app ignores.
  - **Aliases exported:** `UserRole, Profile, LoginResponse, CaseDto, CaseListDto, CaseListQuery, CreateCaseBody, DashboardDto, CaseStatus, CasePriority, SlaState, UserListDto, UserDto, NotificationListDto, CaseAuditDto, CommentListDto, DocumentListDto, InfoRequestListDto, AuditListDto, SlaComplianceReportDto, AgeingReportDto, VolumeByCategoryReportDto, VolumeByOrganisationReportDto, RepWorkloadReportDto, CaseCategoryListDto, CaseTypeListDto, DepartmentListDto, EntityListDto, BusinessUnitListDto, ClosureOutcomeListDto, RoutingRuleListDto`. Baselines unchanged: lint 143, tsc 35.
  - **Port note:** the backend `.env.example` default `PORT` is 3000, while this repo's `api:types` and `.env.example` use 4000 (the dev backend `.env` sets `PORT=4000`). `types.check.ts` guards fail on `never`, `any` and `unknown` DTOs and use exact `Equal` checks on status/priority/slaState/estimatedValue/requesterName/role.
- **B4 — Session, route guards, permissions.** `src/lib/permissions.ts` is the only permission matrix (`canSee`, `rolesFor`, `isLegal`, `can.*`); `src/lib/auth.ts` holds `meQueryOptions` (`['me']`, 60 s, no retry), `useMe`, `useLogin` (clears the whole Query cache, then seeds `['me']` from the login `user`, which is a full Profile per B2), `useLogout` (always clears the cache and goes to `/login`, even if the request fails) and `useChangePassword`. All app routes moved (git mv) under the pathless `_authed` layout, whose `beforeLoad` requires a session; role-gated children (`new-request`, `reports`, `audit`, `users`, `master-data`, `rules`) add `requireNav(..., '<key>')`. Redirects to the remembered page use `href` (not `to`) so the search string survives.
  - **Redirect safety:** `safeRedirect` accepts only paths starting with a single `/` and containing no backslash; `//host`, `/\host`, absolute URLs and empty values fall back to `/`. Used by the login page and the login route's "already signed in" redirect.
  - **Session expiry:** the handler is registered in `getRouter()` (not a component) so it exists before the first route load. It is a no-op on `/login` and while its own redirect is settling, clears the Query cache immediately and navigates one task later, skipping the navigation if a guard already redirected to `/login` (cold load without a session). The cold load still costs two `/auth/me` + refresh pairs (the guard's, then the login route's own session check after the cache clear); no loop and no error UI.
  - **Legacy shell (until B5/B20):** `LcmsProvider` moved from the root into `_authed.tsx` (so it never mounts on `/login`) and is fed from `useMe()` (real role, name, designation; `signedIn` is always true). The demo role switcher and `setRole`/`setSignedIn` are gone; the legacy Sign out button calls `useLogout`. The legacy sidebar still uses its own role lists, so a link can bounce to `/` via the guard until B5 replaces it.
  - **Baselines after B4:** `npx tsc --noEmit` 33 (32 `lcms-app.tsx`, 1 `lcms-api.ts`; the 2 `login-page.tsx` errors are gone); `npm run lint` 132 problems (125 prettier errors in skeleton files, 7 warnings), down from 143.
- **B4 follow-up — Redirect hardening and guard tidy-up.** `safeRedirect` also rejects any control character (`\x00-\x1f`, `\x7f`): browsers strip tab/newline while parsing URLs, so `/\t/evil.com` would become the protocol-relative `//evil.com`. Child routes' `beforeLoad` now `await requireNav(...)` and return nothing; only `_authed.tsx` returns `{ me }`. A test reads every route file's `beforeLoad` and pins the nav key per route (`/`, `/cases/`, `/cases/$caseId`, `/notifications` none; the six gated routes their own key). The login route shows the form when the session check fails with a non-401 error (server down) instead of erroring. Unused `demoUsers` removed from legacy `lcms-data.ts`. Baselines unchanged: tsc 33, lint 132.
- **B5 — Application shell and shared UI primitives.** `_authed.tsx` renders `AppShell` (sidebar, topbar, user menu, toaster) around every authenticated page. The sidebar is built only from `canSee(me.role, key)` via `layout/nav-items.ts`; the legacy `lcms-app.tsx` sidebar, header, nav list and `Toaster` are gone and its page bodies render inside the shell under a `PageHeader` (until their screens are rebuilt). `LcmsProvider` stays as the bridge for those bodies but only carries `role`/`user`/`signedIn` (its sidebar state, `sessionStorage` use and sign out moved to the shell).
  - **Responsive layout:** below md a hamburger opens a left `Sheet` with the full nav; at md an icon rail (72px) is always visible and the hamburger still opens the full sheet; from lg a 240px sidebar that collapses to the rail, remembered in `localStorage` key `lcms-sidebar` (`collapsed`/`expanded`, try/catch). The layout is CSS-driven (Tailwind `md:`/`lg:`), so it is correct before JavaScript measures anything; `useBreakpoint()` (matchMedia + `useSyncExternalStore`, `'lg'` without a window) drives only the components whose markup differs (`ResponsiveDialog`, `ResponsiveTable`, `FilterSheet`). Touch targets are 44px up to lg (tablets are touch devices too) and 36-40px from lg. The topbar title truncates; the topbar and main area respect safe-area insets, and the viewport meta now has `viewport-fit=cover` so `env(safe-area-inset-*)` is non-zero on notched phones. The shadcn `Input`/`Textarea` switch to 14px text at lg instead of md, so inputs stay 16px on tablets (no iOS zoom).
  - **Primitives:** `ResponsiveDialog` (Dialog from md, vaul Drawer below with `max-h-[90dvh]`, scrolling body and sticky safe-area footer; footers submit a form in the body with `form="<id>"`; optional `drawerBelow="lg"`), `ConfirmDialog` built on it (not on `AlertDialog`, per the controller), `ResponsiveTable` (table from md in an `overflow-x-auto` wrapper with a sticky header that sticks when the caller gives the wrapper a max height via `className`; tappable cards below md), `FilterSheet` (inline from lg, "Filters (n)" drawer below), `Pagination`, `EmptyState`, `ErrorState`, `PageHeader`, the badges, `labels.ts` and `format.ts`. Added oklch tokens `--success`, `--success-foreground`, `--warning-foreground`, `--danger-foreground` (dark text on the soft tone backgrounds); the blue palette is unchanged.
  - **Change password:** `change-password-dialog.tsx` posts `{ currentPassword, newPassword }` through `useChangePassword` (confirmation and the backend's min 8 checked client-side; the backend's "Current password is incorrect" is shown inline). The backend revokes all refresh tokens on success, so this session ends when its access token expires.
  - **Baselines after B5:** `npx tsc --noEmit` 32 (31 `lcms-app.tsx`, 1 `lcms-api.ts`); `npm run lint` 104 problems (97 prettier errors in skeleton files, 7 warnings). New files clean.
